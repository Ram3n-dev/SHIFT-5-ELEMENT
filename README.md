# Лимит+

Финансовый помощник для студентов 18–25 лет со стипендией. Отвечает на один вопрос: **сколько можно тратить в день, чтобы дожить до стипендии без минуса**. Учитывает обязательные траты и резерв, а перед покупкой показывает, как она изменит дневной лимит.

Главный принцип: **числа считает код, объяснение только пересказывает готовый расчёт**. Модель не считает лимит и не даёт советов про кредиты, займы, рассрочку, инвестиции и банковские продукты.

## Основной сценарий

1. Студент открывает Лимит+ и в онбординге вводит: карта 4 200 ₽, наличные 800 ₽, накопления 0 ₽, дата стипендии через 10 дней, обязательные траты 1 200 ₽, резерв 400 ₽.
2. Приложение считает: доступно 5 000 ₽, свободно 3 400 ₽. На главной: «До стипендии: 10 дней. Можно тратить 340 ₽ в день».
3. Студент добавляет расход «Кофе, 180 ₽». Баланс и дневной лимит пересчитываются сразу (322 ₽ в день).
4. На экране «Покупка» вводит «Наушники, 650 ₽» и видит: до покупки 340 ₽ в день, после — 275 ₽, изменение −65 ₽, вывод «Можно купить».
5. Кнопки «Почему такой лимит?», «Что изменится после покупки?», «Как снизить риск?» дают короткое объяснение.

> Кнопка «Заполнить демо-данными» в онбординге подставляет эти числа.

## Запуск в Docker

Нужен только Docker.

```bash
docker compose up --build
```

Приложение откроется на http://localhost:8080. Порт меняется в `.env` (скопируйте `.env.example`). Backend наружу не открыт: nginx сам передаёт ему запросы `/api`.

## Запуск для разработки

**Backend** (нужен .NET 10 SDK):

```bash
cd backend
dotnet run --project LimitPlus.Api
```

API будет на http://localhost:5080. Готовые запросы для проверки лежат в `backend/LimitPlus.Api/LimitPlus.Api.http`.

**Frontend** (нужен Node.js 20.19+ или 22):

```bash
cd frontend
npm install
npm run dev
```

Интерфейс будет на http://localhost:5173. Vite проксирует `/api` на backend (порт 5080), поэтому CORS настраивать не нужно.

## Тесты

## API

Поля в JSON — в snake_case. Поле `today` необязательное: браузер передаёт свою дату, потому что сервер может работать в другом часовом поясе.

### POST /api/calculate — дневной лимит

```json
{
  "accounts": [
    { "id": "card-1", "name": "Карта", "type": "card", "balance": 4200, "include_in_spending": true },
    { "id": "cash-1", "name": "Наличные", "type": "cash", "balance": 800, "include_in_spending": true }
  ],
  "stipend_date": "2026-10-06",
  "manual_mandatory_expenses": 1200,
  "reserve": 400,
  "recurring_expenses": [],
  "today": "2026-09-26"
}
```

Ответ:

```json
{
  "days_until_stipend": 10,
  "total_balance": 5000,
  "mandatory_expenses": 1200,
  "reserve": 400,
  "free_money": 3400,
  "daily_limit": 340,
  "status": "safe",
  "message": "Ваш ориентир — до 340 ₽ в день.",
  "upcoming_payments": []
}
```

`upcoming_payments` — регулярные платежи, которые попали в обязательные траты. Их показывает главная страница.

### POST /api/purchase-check — проверка покупки

```json
{
  "total_balance": 5000,
  "stipend_date": "2026-10-06",
  "mandatory_expenses": 1200,
  "reserve": 400,
  "purchase_name": "Наушники",
  "purchase_amount": 650,
  "today": "2026-09-26"
}
```

Ответ:

```json
{
  "balance_after": 4350,
  "daily_limit_before": 340,
  "daily_limit_after": 275,
  "limit_change": -65,
  "decision": "safe",
  "message": "Покупка укладывается в ваш финансовый план. Дневной лимит снизится на 65 ₽."
}
```

### POST /api/explain — объяснение готового расчёта

Ничего не считает, только объясняет переданные числа. `topic`: `why_limit`, `purchase_impact` или `reduce_risk`.

```json
{
  "topic": "why_limit",
  "days_until_stipend": 10,
  "total_balance": 5000,
  "mandatory_expenses": 1200,
  "reserve": 400,
  "free_money": 3400,
  "daily_limit": 340
}
```

Ответ: `{ "text": "Сейчас доступно 5 000 ₽: …", "source": "template" }`. Если чисел для темы не хватает — «Данных недостаточно для точного объяснения.»

Ошибки возвращаются с кодом 400 в формате ProblemDetails, например, если дата стипендии уже прошла.

## Финансовые формулы

Все формулы — в `backend/LimitPlus.Api/Services/BudgetCalculator.cs`. Фронтенд их не дублирует.

```
total_balance      = сумма балансов счетов с include_in_spending = true
days_until_stipend = дата стипендии − сегодня   (сегодня считается, день стипендии — нет)
mandatory_expenses = ручные обязательные траты
                   + включённые регулярные платежи с сегодня по день стипендии
free_money         = total_balance − mandatory_expenses − reserve
daily_limit        = max(0, free_money / days_until_stipend)

balance_after      = total_balance − purchase_amount
daily_limit_after  = max(0, (balance_after − mandatory_expenses − reserve) / days_until_stipend)
limit_change       = daily_limit_after − daily_limit_before
```

Суммы округляются до целых рублей, дневной лимит — вниз, чтобы не показывать больше, чем есть. Дата стипендии должна быть позже сегодняшнего дня.

**Статус бюджета**

| Статус | Условие |
|---|---|
| `safe` | лимит 200 ₽ в день и больше |
| `warning` | лимит меньше 200 ₽ в день |
| `critical` | лимит 0 ₽: после обязательных трат и резерва свободных денег нет |

**Вывод по покупке** (проверяется сверху вниз)

| Вывод | Условие | В интерфейсе |
|---|---|---|
| `not_recommended` | `balance_after < 0` | «Лучше отложить» |
| `critical` | `daily_limit_after = 0` или `total_balance < mandatory_expenses + reserve` | «Лучше отложить» |
| `warning` | лимит падает на 20% и больше | «Можно купить, но с осторожностью» |
| `safe` | лимит падает меньше чем на 20% | «Можно купить» |

> Наушники за 650 ₽ снижают лимит с 340 до 275 ₽ — это −19%, поэтому по правилу 20% вывод `safe`. Пример `warning`: покупка за 1 000 ₽ (лимит 240 ₽, −29%).

## CSV-импорт

Файл обрабатывается **только в браузере** и не отправляется на сервер.

```
date,description,amount,category
2026-09-25,Стипендия,2500,Стипендия
2026-09-26,Продукты,-450,Еда
2026-09-26,Проезд,-70,Транспорт
```

- `amount > 0` — доход, `amount < 0` — расход, ноль — ошибка.
- Дата в формате ГГГГ-ММ-ДД. Разделитель — запятая или точка с запятой, значения можно брать в кавычки.
- Категории расходов: Еда, Транспорт, Учёба, Связь, Подписки, Здоровье, Развлечения, Другое. Доходов: Стипендия, Подработка, Перевод, Другое. Незнакомая категория попадает в «Другое».
- Если в файле есть ошибки, приложение показывает строки с ошибками и ничего не импортирует.
- Пользователь выбирает счёт. Операции сохраняются в localStorage, баланс счёта меняется на сумму операций.

**Демо-файлы.** Пройдите онбординг с демо-данными и импортируйте файл на «Карту»:

| Файл | Итог по файлу | Лимит после импорта | Статус |
|---|---|---|---|
| `normal_budget.csv` | −300 ₽ | 310 ₽ в день | safe |
| `warning_budget.csv` | −1 800 ₽ | 160 ₽ в день | warning |
| `critical_budget.csv` | −3 500 ₽ | 0 ₽ в день | critical |
| `broken_example.csv` | — | — | экран ошибок CSV |

## Объяснения и языковая модель

По умолчанию объяснения строятся по безопасным шаблонам, API-ключи не нужны. Модель подключается через переменные окружения (или секцию `Llm` в `appsettings.json`) к любому OpenAI-совместимому API, например к Ollama:

```bash
LLM_ENABLED=true
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_MODEL=название-модели-из-ollama-list
```

Модель получает готовые числа и текст шаблона и только переписывает его простыми словами. Ответ модели показывается, только если в нём не больше 70 слов, нет чисел, которых не было во входных данных, и нет тем про кредиты, займы, рассрочку, инвестиции и вклады. В остальных случаях — если модель выключена, недоступна или ответила плохо — пользователь видит шаблон.

## Приватность

- Данные сохраняются только в браузере этого устройства (localStorage). Кнопка «Удалить мои данные» в настройках стирает их.
- Backend ничего не хранит: получил числа, посчитал, вернул ответ. Суммы и операции не пишутся в логи.
- CSV-выписка разбирается в браузере и не отправляется на сервер.
- Лимит+ не запрашивает логин, пароль, коды подтверждения и доступ к банковскому приложению.
- Все демо-данные синтетические.

## Ограничения

- **Расчёт является ориентиром, а не финансовой рекомендацией.**
- MVP не работает с банковскими API, не читает SMS и push-уведомления. Данные вводятся вручную или импортируются из учебного CSV.
- Нет авторизации и синхронизации между устройствами: данные живут в одном браузере.
- Регулярный платёж учитывается один раз до стипендии. Если до стипендии больше месяца, второй платёж не добавится.
- Сервис не проводит платежи и переводы, не предлагает кредиты, займы, рассрочку и инвестиции.
